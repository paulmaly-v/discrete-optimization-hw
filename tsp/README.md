## Запуск

```bash
./run.sh
```

Скрипт собирает `main.cpp` и запускает чекер на шести тестах. Чекер проверяет перестановку точек и независимо пересчитывает длину цикла

## 1. NN жадник

Начальный маршрут строится из точки 0, дальше выбираем ближайшуюточку. Асимптотика `O(n²)`

Метод быстро строит допустимый маршрут, но естественно неоптимальный, был взят всего один слабый порог в тестах

## 2. 2-opt

Следующее улучшение заменяет два несоседних ребра `(a,b)` и `(c,d)` на `(a,c)` и `(b,d)`. Для этого участок от `b` до `c` разворачивается. Изменение длины считается так:

```text
delta = dist(a,c) + dist(b,d) - dist(a,b) - dist(c,d)
```

Принимаем только сокращения длины. Проходы повторяются до отсутствия улучшений или ограничения по времени

Результаты первых двух этапов:

| Тест | NN | 2-opt | Скор после 2-opt |
|---|---:|---:|---:|
| `tsp_51_1` | 506.363165 | 444.859890 | 3 |
| `tsp_100_3` | 25138.785453 | 22262.066620 | 3 |
| `tsp_200_2` | 36226.221438 | 32335.692099 | 3 |
| `tsp_574_1` | 47054.947447 | 39691.838201 | 3 |
| `tsp_1889_1` | 391470.445492 | 345794.433955 | 3 |
| `tsp_33810_1` | 78478867.030224 | 71274888.089256 | 3 |

После 2-opt получилось 18/30. Основная проблема это квадратичный перебор

## 3. Списки кандидатов

Для каждой точки сохраняем 40 ближайших точек. При поиске замен 2-opt рассматриваем новые соединения с этими кандидатами

Списки строятся один раз за примерно квадрат, по памяти`O(40n)`. За проход оценивается порядка `40n` замен, но сам разворот участка и обновление позиций требуют дополнительной работы. В отдельном сравнении на большом тесте длина уменьшилась, а время примерно в 7 раз, правда новых порогов не преодолели

## 4. Повторный локальный поиск

Для выхода из локального оптимума делим маршрут на четыре непустых участка и перестраиваем по схеме `A B C D -> A D C B`. После перестроения пытаемся делать локальные улучшения

В промежуточной версии с одним 2-opt по кандидатам эта схема дала 24/30, сильные пороги на первых трех тестах 

## 5. Or-opt

Для расширения соседства добавлены переносы одной, двух или трех последовательных точек в другое место маршрута. Проверяется также разворот переносимого участка

Места вставки выбираются по спискам ближайших кандидатов. Перенос принимается только при уменьшении длины. Для быстрого изменения маршрута используются массивы предыдущей и следующей точки `prev` и `next`

В итоговой версии чередуются 2-opt и Or-opt, пока находятся улучшения. Эта комбинация применяется и к начальному маршруту, и после каждой перестройки double-bridge. В Or-opt длины участков перебираем от 1 до 3

## Итог

В итоговом варианте на задачах с `n <= 2000` сначала выполняем обычный 2-opt. Для больших задач этот этап пропускается из-за стоимости полного перебора, и поиск сразу использует кандидатов. Далее делаем перестройки с double-bridge. Построение кандидатов и весь повторный поиск ограничиваем 40 секундами
