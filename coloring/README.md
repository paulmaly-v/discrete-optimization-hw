# Coloring

## Запуск:

```
./run.sh
```

## 1. Простой жадник

Каждой вершине присваиваем минимальный цвет, которого нет у уже покрашенных соседей. Раскраска всегда допустима, но результат зависит от порядка вершин

| Тест | Цветов | Скор |
|---|---:|---:|
| `gc_50_3` | 9 | 0 |
| `gc_70_7` | 23 | 0 |
| `gc_100_5` | 23 | 0 |
| `gc_250_9` | 100 | 0 |
| `gc_500_1` | 20 | 0 |
| `gc_1000_5` | 127 | 0 |

С таким простым решением ни один порог не был пройден

## 2. DSatur

Далее я использовал метод Dsatur - выбирать порядок во время раскраски. Степень насыщения вершины равна количеству различных цветов у её покрашенных соседей. Этот алгоритм выбирает непокрашенную вершину с максимальным насыщением, а при равенстве выбирает с наибольшим числом непокрашенных соседей. Цвет назначается так же, как в жаднике

Время получается квадратичное

| Тест | Цветов | Скор |
|---|---:|---:|
| `gc_50_3` | 7 | 3 |
| `gc_70_7` | 21 | 0 |
| `gc_100_5` | 19 | 3 |
| `gc_250_9` | 91 | 3 |
| `gc_500_1` | 16 | 5 |
| `gc_1000_5` | 115 | 3 |

Раскраски получились сильно лучше

## 3. Перестановки классов

Из лучшего решения строятся классы вершин по цветам. Классы переставляются, вершины выписываются целыми классами, после чего граф заново раскрашивается жадником

Чередуются порядок по убыванию размера классов, обратный и рандомный. Исходя из методички, повторная жадная раскраска использует не больше цветов, чем исходная

| Тест | Цветов | Скор |
|---|---:|---:|
| `gc_50_3` | 6 | 5 |
| `gc_70_7` | 17 | 5 |
| `gc_100_5` | 16 | 5 |
| `gc_250_9` | 77 | 5 |
| `gc_500_1` | 16 | 5 |
| `gc_1000_5` | 108 | 3 |

Итого 28 баллов

## 4. TABUCOL

Далее попробовал метод, который пытается каждый раз уменьшать кол-во цветов на 1. Для начального решения удаляется наименьший класс, его вершины распределяются по оставшимся цветам с минимальным числом новых конфликтов

Число цветов внутри попытки фиксировано, кол-во конфликтов - количество ребер с одинаковыми цветами концов. Пытаемся перекрасить конфликтную вершину. Если `count[v][c]` это число соседей вершины `v` цвета `c`, то при переходе из цвета `a` в `b` изменение числа конфликтов равно:

```text
delta = count[v][b] - count[v][a]
```

Выбираем лучшее разрешенное такого рода движение, даже если оно увеличивает число конфликтов. Среди движений с одинаковой оценкой делаем рандомный выбор (без этого по тестам не было значительных улучшений). После перекраски возврат вершины в прежний цвет временно запрещаем (чтобы не двигаться туда-обратно). Запрет можно нарушить, если улучшается минимальное число конфликтов за текущую попытку

Запрещаем на кол-во итераций равное `1 + floor(0.6 * conflicts) + r`, r - рандомное число (формулу брал из книжки a guide to graph colouring). Есть ограничения по времени и количеству итераций

Соответственно, при нуле конфликтов новая раскраска сохраняется и начинается попытка уменьшить число цветов ещё раз. Если конфликты остались, поиск заканчивается без повторного запуска для того же `k`. Возвращается последняя допустимая раскраска

| Тест | Цветов | Скор |
|---|---:|---:|
| `gc_50_3` | 6 | 5 |
| `gc_70_7` | 17 | 5 |
| `gc_100_5` | 15 | 5 |
| `gc_250_9` | 75 | 5 |
| `gc_500_1` | 14 | 5 |
| `gc_1000_5` | 96 | 5 |

## Итог

Итого получилось 30 баллов за тесты
