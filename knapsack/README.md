# Задача о рюкзаке

## Запуск

```bash
./run.sh
```

Скрипт собирает `main.cpp` и запускает чекер на шести оцениваемых тестах. Чекер проверяет вес и пересчитывает стоимость выбранных предметов

## 1. Жадный алгоритм

Сначала я отсортировал предметы по убыванию удельной стоимости и добавлял их в рюкзак, если они помещались

Алгоритм работает за `O(n log n)`, но не гарантирует оптимальный ответ, иногда перед более выгодной комбинацией он успевает занять место одним тяжёлым предметом

| Тест | Стоимость | Скор |
|---|---:|---:|
| `ks_30_0` | 90000 | 0 |
| `ks_50_0` | 141956 | 3 |
| `ks_200_0` | 100062 | 3 |
| `ks_400_0` | 3966813 | 3 |
| `ks_1000_0` | 109869 | 3 |
| `ks_10000_0` | 1099870 | 3 |

Основная проблема видна на `ks_30_0`: решение корректное, но не проходит даже первый порог

## 2. ДП

Дальше я реализовал дп по вместимости. `dp[w]` хранит максимальную стоимость, которую можно получить при вместимости `w`. Для каждого предмета массив обновляется справа налево:

```text
dp[i] = max(dp[i], dp[i - cur_w] + cur_v)
```

Обход справа налево нужен, чтобы один предмет не использовался несколько раз. Для восстановления ответа отдельно хранится, каким предметом было улучшено состояние

Время работы `O(nW)`. Значения дп занимают `O(W)` памяти, а таблица восстановления `O(nW)` бит. Чтобы не выделять слишком много памяти, DP запускается только при `nW <= 120000000`. Как итог на части тестов находится оптимум, а на части лучший результат дает жадник

| Тест | Стоимость | Скор |
|---|---:|---:|
| `ks_30_0` | 99798 | 5 |
| `ks_50_0` | 142156 | 5 |
| `ks_200_0` | 100236 | 5 |
| `ks_400_0` | 3966813 | 3 |
| `ks_1000_0` | 109899 | 5 |
| `ks_10000_0` | 1099870 | 3 |

ДП для последних двух тестов требует несколько миллиардов состояний, поэтому увеличивать лимит для них бессмысленно

## 3. Метод ветвей и границ

Для больших весов я написал метод ветвей и границ. Предметы снова сортируются по удельной стоимости. В каждом узле рассматриваются две ветви, взять следующий предмет или пропустить его

В качестве начального допустимого решения используется жадник. Верхняя граница считается решением дробного рюкзака. Оставшееся место заполняется предметами по удельной стоимости, а последний предмет разрешается взять частично. Если эта оценка не превосходит лучшее найденное значение, поддерево отсекается

В худшем случае дерево экспоненциальное, поэтому я ограничил поиск числом рассмотренных узлов. Проверил несколько значений лимита:

| Лимит узлов | `ks_400_0` | `ks_10000_0` |
|---:|---:|---:|
| 10 000 | 3967168 | 1099870 |
| 100 000 | 3967180 | 1099881 |
| 1 000 000 | 3967180 | 1099893 |

На миллионе узлов оба теста проходят сильный порог и укладываются в ограничение по времени. Я также пробовал начинать этот метод с нулевой нижней границы вместо жадного решения. На этих тестах итоговые значения не изменились, т.к. из-за порядка обхода хорошее решение и так находится быстро. Жадную инициализацию всё равно оставил, так как в общем случае она позволяет раньше отсекать ветви

Итого программа выбирает лучший результат жадника, дп и метода ветвей и границ

| `ks_30_0` | 99798 | 5 |

Получены все сильные пороги. ДП доказывает оптимальность на четырёх тестах (т.к. это по сути индукция), где полностью просматривает таблицу состояний. Для метода ветвей и границ оптимальность не гарантирована, потому что поиск ограничен числом вершин дерева
